# Produce an explainer video

Create a complete teaching video and recoverable sources. Default to free local tools, native Kokoro `af_heart` at speed 1.0, and a vertical phone-readable export. Honor explicit voice, format and style choices. Detect capabilities before promising a render. No model weights, private data or reference artwork belong in this skill.

At **each asset deliverable**, use independent subagent review and handle routine fixes internally. Add a dedicated [visual "diva" reviewer](references/visual-diva-reviewer.md) for every scene, alongside separate technical/editorial scopes, with a high bar for striking, attractive graphics and purposeful motion. Follow [the bounded review loop](references/production.md#per-deliverable-review-loop): at most **three rounds per scene/asset deliverable**, shared across reviewers, stop early when no actionable findings remain, and record findings, fixes and verification. Preserve actual inspection limits. At the cap, surface unresolved critical or material visual findings; never silently approve, reset the cap by changing reviewers or invent extra rounds.

## Production sequence

1. Inspect the existing topic catalog and artifacts. Use one current tracker and one current production document. Preserve accepted work; distinguish a new topic from a remake. Start from [the production template](assets/production.md) and [tracker schema](assets/tracker.json).
2. Ground claims in actual primary/reference passages. Write the production document before rendering: audience, learning outcome, scope, source anchors, practical implementation, assumptions and limits. Open with **what we learn and why it matters**, then the real-world actors, goal, failure and stakes. Define terms, show normal operation, then failures, tradeoffs and recap. Complete explanation determines duration; no arbitrary cap.
3. Draft the narration and storyboard. Give each explanation a fitting scene or diagram, visible input/current/output states, spoken cue, causal action and transition. One continuing example gives continuity; one diorama with camera zooms does not give enough explanatory variety. Read [production and review gates](references/production.md) for independent technical and editorial responsibilities.
4. Build and **deliver a representative narrated sample for every episode, always before full production**. Include actual motion, screen-space karaoke captions, a transition and an explanatory diagram. A still, silent intro or another episode's sample cannot pass this gate. Review at native pace in the bounded independent loop, record meaningful feedback and the selected configuration, and deliver the sample. When full production is already authorized, continue after internal gates pass without asking the user to approve each routine revision. Involve them for a material creative decision, unresolved critical finding or actual permission blocker; do not infer full-video acceptance from sample delivery.
5. Implement the full timeline with [visual and motion guidance](references/style.md). Create fresh episode-specific artwork; reuse tools/design language rather than recycled episode art. Check pixel/crop resolution, aspect ratio and coherent geometry, rebuilding soft assets instead of enlarging old bitmaps. The independent visual reviewer covers every scene ID/time range using keyframes, temporal evidence, transitions and actual encoded master/phone evidence; static sampling does not prove motion or listening. Preserve useful layouts, narration and timing during depth polish. Keep a visibly matte, chalk-wiped/dry-grain dark background alongside clean dimensional/isometric objects; objects need not all be chalk-textured, and a flat gradient alone cannot replace the established board. Use subtle raised diagrams, cyan/lavender, level labels, internal actor/screen/LED action, quiet event sounds and fine curved directional light paths. Stable teaching holds and tasteful restraint matter; reject generic repeated blocks, clutter and camera-only motion when the mechanism needs visible action.
6. Checkpoint exact art, script, WAV, cues, dependencies and code before long rendering. Run a **native-paced animatic editorial gate** plus every-frame caption/crop/path/glow/actor audits before expensive encoding. Review transitions and transit states. Freeze repaired sources; prior-cut reviews do not approve changed code.
7. Render bounded work units from the frozen source lock. Follow [local tools and contracts](references/tools.md) for portable helpers, capability detection, source-set checks, exact WAV preservation, alpha/camera/overlay contracts and stop/resume behavior. Never shorten or stretch narration to fit frame boundaries.
8. Independently review the **encoded master and phone copy**, with separate visual, editorial and technical verdicts. Measure integrated loudness and true peak on both final encodes; follow [measured normalization and sync checks](references/loudness.md), preserve native voice/rate/timing, and remeasure after any AAC correction. Repair and recheck within each scene/asset's shared three-round cap, stopping early when findings are resolved. Technical correctness alone does not establish an engaging, varied video. If independent reviewers or playback are unavailable, report the missing gate; never relabel self-review as independent.
9. Deliver playable video, production document, captions, exact WAV/cues and verified recovery ZIP. For quiet destination playback or size rejection, use [short compatibility diagnostics and bounded delivery](references/playback-delivery.md), obtain actual listening feedback, and preserve approved audio during visual work. Do not sacrifice approved visuals merely to fit an attachment; retain the full-quality master and use reviewed higher-quality parts or a supported authorized alternative when needed, explaining the tradeoff. Save to the user's requested destination and preserve existing Library identities when applicable. Update the existing tracker and guide with evidence; a tool error does not establish delivery. A publishing title/description is a draft when requested. **Delivered, user-ready and published are separate states. Publish only with authorization.**

Every report must distinguish frame sampling, automated full decode, continuous watch/listen, waveform checks and independent forced alignment. Kokoro cues are model estimates. Report inspected timecodes, limits and remaining blockers, without claims of watching or listening unsupported by actual playback.
