# Neon Chalk Systems

Reusable direction for the existing Neon Chalk Systems visual language. This
reference carries forward the recovered style source and the teaching choices
supported by the [Cloudflare case inspection](cloudflare-cinematic-decomposition.md).
It is shared guidance for the three video workflows, not a separate skill or a
replacement for the episode brief, factual sources or existing review process.

## Visual language

Use deep matte-black chalkboard EVERY scene/timestamp after opening through normal/alternatives/human bridge/closing for the existing "Neon Chalk Systems" style guide; never white/cream/parchment/light background, reject any light output. Use light chalk-like contours and
restrained luminous accents where this style fits the brief. Keep texture and glow
behind the lesson. Clear silhouettes, spatial grouping and contrast should make
the foreground idea easy to find. Contextual illustrations can use depth and
perspective; mechanism diagrams can stay flat and precise in the same palette.

The recovered style source associates cyan/blue with flow, green with healthy or
successful state, yellow/orange with attention and magenta with exceptional state.
An episode can give a distinct lane, object or state a more specific color,
such as violet for configuration. Establish that meaning, retain it across cuts
and pair it with labels, shapes or symbols. Orange also appears as a brand accent
in the Cloudflare reference; do not read every orange outline as a failure.

Keep the same person, request, document, destination or module recognizable when
the view changes. Reuse object names and visual anchors, then change the state
that matters. Do not let decorative arrows, labels or props assert system
relationships absent from the factual model.

## Narrative and scene decisions

- **Establish the baseline before the human goal.** For new videos, explain the
  concept in plain language and state concrete learning objectives first, using
  [TEACH-OPEN-01](teaching-opening.md). Then a named person's goal can clarify
  stakes. The historical case starts with fictional Sam seeking museum hours;
  that observed sequence does not override the current opening requirement.
  A human scenario is optional; identify invented scenarios as illustration.
- **Say the meaning before the term.** Explain the destination server before
  calling it the origin; explain a behavioral trait before calling it a feature.
  Match each new term to one visible object or action.
- **Establish normal behavior, then perturb it.** Give the viewer a success path
  and an expected result before introducing the changed input, constraint or
  failure. The later comparison then has a stable reference point.
- **Separate causes that travel independently.** For this outage, the browser
  request and centrally prepared configuration file occupy separate lanes. Show
  where the lanes meet without implying that the user's click builds the file.
  Use separate lanes only when the underlying relationship warrants them.
- **Build the mechanism in understandable stages.** Introduce actors, the active
  route, an internal module and its separate input as the explanation needs them.
  Leave time to read the current state and understand its result before the next
  dependency. Sparse diagrams still need enough screen time.
- **Use concrete comparisons.** Match a receiving capacity with an oversized
  input, or compare two software versions under the same bad input. Keep the
  examples and conditions aligned. Do not invent numbers to make a comparison
  symmetrical or easy to animate.
- **Use contextual resets and motivated returns.** Briefly return to the human
  task or an unchanged object to clarify what did and did not change. The museum
  page between metadata generation and the capacity explanation separates site
  content from internal configuration. A later return to Sam closes the question.
  A cutaway should give new understanding, not merely decorate a diagram.
- **Change scene type for a teaching reason.** Illustrations can establish stakes,
  diagrams can explain causality, and a map can establish distribution. Choose
  what the idea needs; do not turn the observed sequence into a scene quota.
- **Keep the recap inside the established language.** Return to recognizable
  actors and restate the causal chain with a few large labels. Preserve contrast
  and typography rather than covering the illustration with unrelated text blocks.

## Readability and factual overlays

Generous negative space does not establish readability. The Cloudflare technical
views leave substantial empty canvas while several module, query and rule labels
remain small. Size the labels that carry the lesson for the actual delivery
format, reduce subordinate text and inspect the encoded result at its intended
viewing size. A readable heading cannot compensate for an unreadable condition.

Illustrated screens, clocks, maps, error messages and callouts remain factual
claims when viewers could read them as evidence. Use a generic failure display
when the source does not support a precise diagnostic code. In particular, do
not copy the case's early 522 timeout tablet as a depiction of the later FL2
panic. Distinguish schematic quantities, illustrative clocks and historical
timestamps, and label a later follow-up as later.

The reference does not establish reliable bottom captions. Preserve the existing
caption requirement where supported; large scene labels and recap cards serve
different purposes from a synchronized transcript. Avoid generated microtext
that looks like meaningful technical annotation.

## Vertical adaptation of an existing wide video

Adapt scenes around their essential relationships. A wide two-lane diagram may
need a full-width inset plus a large explanation card, a stacked restatement, or
separate focused views that retain the connection. A contextual illustration may
support a different crop. A fixed center crop can remove the browser, origin,
configuration source or rule condition and change the lesson.

Enlarge or restate the main labels when the source diagram cannot remain readable.
Check the browser-to-intermediary-to-origin relationship, both causal lanes,
version distinctions and numbered recovery order after each layout change.
Preserve native audio and requested duration when changing only presentation.
Do not fit a wide lesson by accelerating its narration.

If adding learning cards, identify them as editorial summaries. They are not
verbatim captions. Machine ASR in coarse chunks is an aid to understanding;
verify wording and alignment before presenting it as synchronized speech text.

## Evidence scope

The Cloudflare case supports these choices through sampled pixels and approximate
machine transcription. It does not prove motion quality, narration cadence,
prosody, exact cue alignment or uninterrupted comprehension. Use the existing
scene and encoded-media reviews for a new deliverable. This reference adds no
approval gate and does not certify the inspected video as fully QA passed.
