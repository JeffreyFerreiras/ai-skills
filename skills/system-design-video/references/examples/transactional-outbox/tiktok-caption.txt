Order saved. Confirmation email never sent. Save the order with EF Core, then publish OrderPlaced to the message broker, and you have two writes that nothing ties together: if the app crashes between them or the broker is down, the order is committed but the event is gone, so email never sends and inventory never reserves. Publish first instead, and a rollback leaves everyone reacting to an order that doesn't exist. The fix is a transactional outbox: add an OutboxMessage to the same DbContext and call SaveChanges once, so the order and the event commit together or not at all. A background relay polls the outbox table, publishes each unsent message and marks it sent; if the broker is down, the message waits and the relay tries again. Trade-offs: delivery is at-least-once, so make consumers idempotent and skip repeats, polling adds a little delay, and you should clean out sent rows. #systemdesign #dotnet #csharp #efcore #microservices #backend #softwarearchitecture
