# Production record

Presentation requirements are not technical evidence. Copy this template into
the video project or use these fields in its existing record. Leave unperformed
checks pending; remove branches outside the requested deliverable.

## Brief and checkpoint

- Learning question, audience, what/problem/why/solution opening, ordered learning
  preview, concrete example, limits, and source/claim locators:
- Exact spoken hook, promise/payoff, first-frame phone-safe design, optional
  supporting animated cover, lock/review before full narration, body-audio hashes:
- Hook form (question/phrase/claim), relevance and specific interest, claim sources,
  payoff, natural landing time, picture alignment, ad-evidence versus workflow scope:
- Requested deliverable, format, duration constraint, style/reference identities:
- For shorts, natural-pace runtime estimate within the 90-180-second target;
  any over-180 warning/reason, user choice of approved longer runtime or
  narrower/split scope, exact approval and production boundary; actual runtime
  and any unexpected overrun disposition, retaining review budgets:
- Capability preflight: renderer/media tools, selected voice/alignment, reviewer
  dispatch, playback/listening, GPU/RAM/storage evidence and unresolved items:
- Voice engine/version, voice/rate, pronunciation choices, WAV/cue paths and hashes:
- Default Kokoro CPU config identity, explicit selected embedding versus unresolved
  voice approval, runtime/asset lock, worker deadline and verified process affinity:
- Native WAV sample rate/channels, any explicit 48 kHz/stereo conversion and unity
  channel mapping, exact-input loudness passes, final-WAV ASR/cue evidence and gaps:
- Laptop identity: exact CPU SKU/NPU generation, OS build, NPU driver, detected
  OpenVINO devices/full names, NVIDIA GPU/VRAM, probe report and unresolved fields:
- Kokoro runtime/model/voice/dictionary revisions and hashes, licenses/notices,
  requested versus evidenced execution device, CPU preprocessing/G2P, fallback
  reason and attempt count, thread/stream limits and worker deadline:
- Roughly 10-second laptop test: measured WAV duration, cold/warm times,
  responsiveness and stutter observations, actual listening intervals, disposition;
  unperformed checks remain pending and do not establish NPU success:
- Native prosody, synthetic reference/transcript/hash and provenance, model/codec
  revisions and dtypes, staged loading, fallback reason, measured timing scope:
- Continuous-take strategy and tested length limits; sentence/scene pause choices,
  waveform boundaries, original PCM checks, sample-offset edit map, new cue hashes:
- Configurable model/runtime/cache roots, any scoped relocation/junction tests
  and rollback evidence; configured finished-video destination:
- Accepted choices, local/external authorization, any reserved sample decision:
- Spec and scene source revision/hashes, assets/fonts/licenses, dependency lock:
- Contract version, event start/completion times and resulting states, caption
  cue precision, preview frame indexes covering travel and completion:
- Render entrypoint, exact commands, output paths, unit/frame ranges and hashes:
- Resume method, completed units, invalidated inputs, next action:

## Loop recovery checkpoint

Keep this Supervisor-owned recovery state in the project's durable task metadata
or a declared sidecar excluded from the candidate digest. Do not copy live state
into the installed skill. Retain the previous last-good checkpoint.

- Schema version, increasing sequence, checkpoint integrity digest, last trusted
  snapshot, current phase, frozen plan and immutable Writer identity:
- Per-dispatch attempt/idempotency key, selected assignment, candidate digest,
  execution handle/status, settled proof, and unresolved/unknown execution:
- Ordered per-command validation receipts bound to the candidate digest and
  workspace; per-round review bindings, decisions, stable finding lifecycle:
- Material revisions, invalidated approvals/resolutions, affected downstream
  gates, consumed reservations on resume, outstanding IDs and next permitted step:
- Actual atomic/persistence mechanism and limitations, reconciliation evidence
  before redispatch, blocked reason or final current-digest approval:

## Final media and delivery

- Encoded identity/hash, dimensions, fps, codecs/channels, frame count/duration:
- Full-decode result and command; audio/video start/end and sync tolerance:
- Integrated LUFS/true peak dBTP, channel convention, target/rationale, exact command:
- Any two-pass repair input/hash, measured filter values, remeasured output/hash:
- Distributed waveform windows/method/lags after repair; actual listening scope:
- Approved intro/body hashes and sample offsets, canonical-word reconciliation,
  ASR disagreements/uncertain boundaries, actual-waveform caption/anchor timing:
- Local handoff path or authorized transfer receipt, whole-file identity evidence:
- Any brief-authorized full-length 1080p chat preview or other requested copy:
  byte limit, measured size, audio preservation evidence,
  encoded visual/audio review, transfer evidence:

Track each state separately with evidence, pending requirements, and the exact
artifact revision. Rendering is not QA, transfer is not acceptance, and acceptance
is not publishing permission.
